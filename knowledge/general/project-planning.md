# Project planning essentials

## Define the problem and goals
Write a one-paragraph problem statement: who is affected, what the gap is, and why it matters. Turn it into SMART objectives: Specific, Measurable, Achievable, Relevant and Time-bound. Separate must-have requirements from nice-to-have features.

## Scope and work breakdown
Create a work breakdown structure (WBS): split the project into deliverables, then into work packages small enough to estimate (typically 1–5 days of effort). Record assumptions and constraints (budget, hardware, data access, ethics approvals).

## Milestones and schedule
Order work packages by dependency, identify the critical path, and set milestones such as requirements freeze, prototype v1, evaluation and final report. Gantt charts or a simple Kanban board (To do / In progress / Review / Done) are enough for student projects. Add buffer time of about 15–20% for integration and testing.

## Risk management
List risks with likelihood and impact, then define a mitigation for each (for example: component lead time → order early and pick a second-source part; model accuracy too low → define a fallback baseline).

## Evaluation
Define success metrics up front (accuracy, latency, cost, user satisfaction, test coverage). Plan how you will measure each one and what baseline you compare against.

## Documentation and communication
Keep a project log, use version control (Git) from day one, and hold short regular reviews with mentors. A good final report covers problem, related work, method, implementation, evaluation, limitations and future work.
